# Working assumptions

These are decisions taken to keep moving while they are unconfirmed. Each one is implemented as written here. To change one, edit this file, the spec, and the decision log together.

| # | Assumption | Why | How to confirm or change |
|---|---|---|---|
| A1 | Brackets are mirrored by hand: in file order `)` opens and `(` closes; `]` opens and `[` closes. | The terminal does not mirror glyphs, so the opening bracket at the right end of a group must look like `)`. | Type a grouped expression in Vim Arabic mode and check it looks right. If not, swap the mapping in the lexer (one table). |
| A2 | Diagnostics are Arabic. Each message is built in file order (numbers least significant digit first), then the whole line is reversed code point by code point before printing. | A plain left-to-right terminal then shows the same picture Vim rightleft shows. | Run any failing assemble and read the error. Known limitation: no letter joining on the terminal. |
| A3 | The Vim Arabic keymap produces Arabic-Indic digits U+0660–U+0669 and the Arabic comma U+060C. | Spec choice. | In Vim, put the cursor on a typed digit / comma and press `ga`. If it shows U+06F0–U+06F9 (Persian digits), decide whether to accept them. |
| A4 | Persian digits U+06F0–U+06F9 are rejected. | Keeps one digit set; easy to relax later. | Same check as A3. |
| A5 | Arabic assembly source files use the extension `.تجميع`. | Full-word naming policy. | Rename freely; nothing depends on it except the test runner glob. |
| A6 | Identifiers use Arabic letters U+0621–U+063A and U+0641–U+064A, `_`, and Arabic-Indic digits (not first). Latin letters are not allowed in identifiers (only inside strings). Extended letters (U+0671 and later, e.g. پ چ گ) are rejected for now. | Smallest unambiguous set. | Widen the character class table if needed. |
| A7 | A number immediately followed by a letter is an error, except: hex letters after a `٠س` marker, and the local label suffixes ق / م after a decimal number. | Avoids silent mis-lexing. | — |
| A8 | Binary operators are left-associative in file order (= reading order on screen). `* /` bind tighter than `+ -`. | Matches how the line is read right to left. | — |
| A9 | Whitespace is ASCII space and tab; lines end with LF. The Arabic semicolon ؛ has no meaning yet (error). | Simplicity. | — |
| A10 | `.شفرة`, `.بيانات`, `.بيانات_للقراءة`, `.بيانات_صفرية` work both as stand-alone directives (like GAS `.text`) and as section names after `.قسم`. | Mirrors GAS. | — |
| A11 | Until pc-relative relocations exist (Phase 2), test programs take addresses with `حمل_علوي_فوري` + `عالي:` and `جمع_فوري` + `أدنى:` (absolute, non-PIE, GNU ld default base). | Phase 1 has no pseudo-instructions. | — |
| A12 | Proposed names, not yet used: pc-relative relocation operators `عالي_نسبي:` / `أدنى_نسبي:`. Pseudo-instruction names will be proposed before Phase 2. | Naming policy needs user approval. | Decide before Phase 2. |

## Added in Phase 1 (assembler v0)

| # | Assumption | Why | How to confirm or change |
|---|---|---|---|
| A13 | Branch targets (`تفرع_إذا_…`) must be a label in the **same section** plus an optional constant. Branches to undefined/external symbols are an error. | GNU as silently turns such a branch into an inverted branch plus a jump (two instructions). That is a pseudo-instruction job; it belongs to Phase 2. | Revisit when pseudo-instructions are designed. |
| A14 | A constant from `.ثابت` may be used in instruction operands **before** the line that defines it (resolved in pass 2). Places that need the value immediately (`.فراغ`, `.محاذاة`, `.ثابت`) need it defined earlier. | Natural two-pass behaviour. GNU as rejects the forward use, so the differential fuzzer skips those cases. | — |
| A15 | `.محاذاة` always aligns, also inside `.شفرة`. Code padding follows GNU: a zero byte to an even offset, a 2-byte `0x0001`, then 4-byte nops. `.شفرة` is padded at its end to its alignment, like GNU. | GNU as ignores `.align 0..2` inside code when data bytes made the offset odd; we treat that as a GNU quirk, not something to copy. | — |
| A16 | A relocation operator applies to one primary: `عالي:رمز`. For symbol + offset use brackets: `عالي:) رمز + ٤ (` (file order, `)` opens). The operator must be the whole operand. | Unambiguous and easy to read. | — |
| A17 | A symbol difference `أ - ب` is a constant when both labels are in the same section; anything else with two symbols is an error. | Enough for lengths (`.ثابت طول، نهاية - رسالة`). | — |
| A18 | Diagnostics display (refines A2): the line is reversed, then runs of Latin characters (paths) are reversed back so they stay readable. `DIAG_ORDER=file` prints file order (used by the tests). | Paths on the command line are usually Latin. | Look at a real error in your terminal and say if the layout is wrong. |
| A19 | The assembler binary is `مجمع`; usage `مجمع دخل.تجميع خرج.o`. No options yet. Exit codes: 0 ok, 1 source errors, 2 usage or I/O. | Full-word naming. | — |
| A20 | Only the four standard sections exist; `.قسم` with any other name is an error. | Enough for Phase 1. | Phase 2 if needed. |
| A21 | Objects are produced as GNU `as -mno-relax` would: no `R_RISCV_RELAX` and no linker relaxation. Relocations always name the target symbol (local labels included), with field contents exactly as GNU writes them. | Makes byte-for-byte comparison possible; relaxation can come with our own linker. | — |
| A22 | Numeric local labels are emitted as GNU-style `.L<n>^B<k>` local symbols, and only when referenced. | Identical symbol tables to GNU. | — |
| A23 | Register names are reserved: they (and `عالي`, `أدنى`) cannot be used as label or constant names. A register number written with a redundant zero (e.g. `وسيط٠٠`) is not a register. | Avoids ambiguity. | — |

## Added in Phase 3 (linker)

| # | Assumption | Why | How to confirm or change |
|---|---|---|---|
| A29 | Usage `رابط ملف_الخرج ملف_كائن...`: the output first, then the objects. No options yet. | Several inputs, one output; no flags to design yet. | Say if you prefer another order or Arabic options. |
| A30 | Fixed layout: text segment at 0x10000 (headers, `.text`, `.rodata`), data segment on the next page (`.data`, `.bss`), inputs in command-line order. | Simple, and reproducible with a GNU ld script for testing. | — |
| A31 | The entry point is always the global `_بداية`. | Matches the tests so far. | An option can be added when needed. |
| A32 | Relocations: the ones in docs/spec-linker.md. R_RISCV_RELAX is ignored (no relaxation). Everything else is an error. | Covers everything our assembler emits, and GNU objects built with or without relaxation (as long as they have no `.align` in code, which needs R_RISCV_ALIGN). | — |
| A33 | Input sections are mapped to the four output sections by name prefix; non-ALLOC sections are dropped; other ALLOC sections are an error. | Keeps the layout fixed. | — |
| A34 | Weak symbols (from GNU objects) work: strong beats weak, undefined weak = 0. | Cheap and standard. | — |
| A35 | The output symbol table keeps named local and global symbols, not `.L` labels. | Useful in objdump/gdb. | — |
| A36 | No archives, scripts, shared libraries, PIE or relaxation yet. | Not needed until the compiler and its runtime library exist. | Archives will be needed for the runtime library (Phase 4). |

## Added in Phase 4 (compiler مترجم, first version)

| # | Assumption | Why | How to confirm or change |
|---|---|---|---|
| A37 | Usage `مترجم رئيسي.غرة خرج.تجميع [مسار_بحث...]`. The compiler follows the imports and writes **one** assembly file for the whole program; you then run `مجمع` and `رابط` (with `lib/runtime/تشغيل.تجميع`). Building the executable in one command, and separate compilation with interfaces stored in objects, come with our object format. | Our own object format (decision 11) is where interfaces live; until then whole-program compilation is simplest and exact. | — |
| A38 | `ليس` binds more loosely than comparisons: `ليس أ == ب` means `ليس )أ == ب(`. | Avoids C's `!a == b` trap. | — |
| A39 | Mixing `و` and `أو` in one expression needs brackets, like mixing bitwise and arithmetic operators. | No hidden precedence between them. | — |
| A40 | Unary minus only applies to signed integers; on an unsigned value it is a compile error (write `٠ - ق` to wrap on purpose). | Negating an unsigned value is almost always a bug. | — |
| A41 | An expression statement must be a call. | `أ + ب؛` does nothing and is a mistake. | — |
| A42 | A local may not reuse the name of a visible local, a declaration of its module or an import alias (no shadowing). | Every name has one meaning in a function. | — |
| A43 | For `غير_مهيأ` variables, only assigning the whole variable counts. Writing a field or element, or taking `@`, needs the variable to be assigned first. | Keeps the definite-assignment rule simple and sound. | — |
| A44 | Allowed implicit conversions: only the safe ones: `^T` → `^ثابت T`, `][T` → `][ثابت T`, `^T` → `اختياري ^T`, `لاشيء` → any optional pointer. Everything else is explicit. | Adding read-only or optional never loses information. | — |
| A45 | ~~`بنية مضغوطة` and calls with more than eight argument words are not supported yet.~~ Resolved: both are implemented. Argument words beyond the eight registers go on the stack in 8-byte words as the RISC-V psABI says (a two-word argument may be split between `وسيط٧` and the stack); tested in both directions against GCC. | Implementation order. | Resolved. |
| A46 | Generated label names are `ت_<number>`, module-level names become `<module path with _>__<name>`; `خارجي`, `عام خارجي` and `رئيسية` keep their raw names. Source file names must be valid identifiers (they become module names). | Valid assembly symbols, no collisions. | — |
| A47 | The standard library starts with `غرة.نصوص`: `اطبع`, `اطبع_سطرا`, `اطبع_عددا`, `اطبع_عددا_سطرا`. Numbers are printed with Arabic-Indic digits in normal text order (most significant first), as text output, not source. | Program output is text for any viewer. | Say if you want another order or Latin digits. |
| A48 | Run-time stops (`عنصر_بفحص`, `شريحة_بفحص`, `حول_بفحص`, `…_بفحص` arithmetic) print an Arabic message on stderr (stored in display order, A18) and exit with code 101. | A fixed, recognisable code. | — |
| A49 | Program entry: `عام دالة رئيسية)(: طبيعي٨` or with one parameter `وسائط: ][][ثابت طبيعي٨`; the runtime builds the argument slices. | Decided shape (decision 30), exact types fixed here. | — |
| A50 | Declarations may also come in any order across modules; constants, enumerations and structures are resolved on demand with cycle detection. A struct that contains itself by value is an error. | Decision 30 says order does not matter. | — |
| A51 | Fields of a `بنية مضغوطة` are read and written byte by byte (one byte load/store per byte), so any field alignment works. Taking the address `@` of such a field, slicing an array field, or `لكل` over an array field is an error, because the result would be a misaligned pointer that ordinary code assumes is aligned. Copy the field into a normal variable first. | A misaligned pointer would make later loads silently slow or trap on hardware without misaligned support; the compiler cannot track it through the type system. | Could add an "unaligned pointer" type later if needed. |
| A52 | ~~Two steps~~ Done: step A was the object itself, the writer in `مجمع`, the reader in `رابط` and the viewer `عارض`; step B adds the module interface with its hash, and archives. The header reserves `interface_size` so step A files stay valid. | The linking model needs the compiler to emit interfaces, which comes after the container works. | Step B in Phase 4. |
| A53 | `مجمع` chooses the format from the output name: a name ending in `.كائن` gives our format, anything else gives ELF. `رابط` chooses by the magic bytes of each input, so ELF and `.كائن` objects can be mixed in one link. | No new command-line options. | — |
| A54 | The PC-relative high/low pair is one fact in our format (the low relocation stores the offset of its high instruction), so the GNU hidden label `.L0 ` is not needed. `رابط` rebuilds an equivalent hidden label internally so one relocation engine serves both formats. | Keeps a single code path; guarantees identical executables. | — |
| A55 | `نداء` stands for both `R_RISCV_CALL` and `R_RISCV_CALL_PLT`; the linker treats them the same (no PLT in a static link). Weak symbols do not exist in our format yet (the assembler has no weak directive). | Nothing to distinguish. | Add a weak flag if a directive appears. |
| A56 | The interface text holds the module's imports and every structure and enumeration, private ones too (without `عام`), so exported signatures may use private types. A change to a private structure therefore changes the interface hash and rebuilds importers. | Simple and always safe. | Could print only the private types that public declarations reach. |
| A57 | A module's object is up to date when it carries exactly the interface region the module would get now (same source hash, same hashes of the imported interfaces). File times are not used. The compiler's own version is not part of it: after updating `مترجم`, delete `بناء/`. | Content hashes need no clock and no extra OS call. | Add a compiler version to the region. |
| A58 | Build mode is chosen when the second argument does not end in `.تجميع`. Further arguments ending in `.o` or `.كائن` are extra link inputs, `.مكتبة` are libraries, anything else is a search path. The start file is `<search path>/runtime/تشغيل.تجميع`, assembled on every build; without it `_بداية` must come from a library or an object. | No option syntax yet. | Options when there are more of them. |
| A59 | A library has no separate symbol index: `رابط` reads the exported symbols of each member directly, repeating until nothing changes; the entry `_بداية` counts as needed. | Nothing can drift out of sync. | An index if libraries get large. |
| A60 | Exported (`عام`) functions and variables are global symbols in the generated assembly, in both modes. Every source module is still parsed and checked on every build; only code generation and assembly are skipped for up-to-date modules. | The checker needs the whole program anyway; checking is fast. | Check against interfaces only, when programs get large. |
| A61 | Bare-metal images (`--عاري`, for `رابط` and `مترجم`): ELF with the code at `0x80000000` (QEMU virt RAM, where `-bios none` starts), `.rodata` after it, `.data`/`.bss` on the next page; headers outside the loaded segments. `_بداية` must be at `0x80000000` (error otherwise). In a bare `مترجم` build, `.تجميع` arguments are assembled into `بناء/` and linked first, and no hosted start file is used. One-file mode is still chosen when the second argument ends in `.تجميع`, so a bare build puts `--عاري` before its assembly files. | QEMU loads ELF segments itself; the entry check catches a wrong file order early. | A raw binary or our own image format for real boards. |
| A62 | `متطاير` codegen: a full `سياج` (fence iorw,iorw) before and after every access. That is stronger than the minimum for sequential consistency, and simple to reason about. | Correct first; a kernel's device accesses are few. | Weaker fences per access kind if profiling ever shows a need. |
| A63 | The OS lives in `os/` in this repository (modules `جهاز.…`, `أساس.…`, root `نواة`), tested by `make os` on `qemu-system-riscv64` (Debian package `qemu-system-misc`). Language stops (index out of range, overflow, failed conversion) print on the UART and power QEMU off with code 101; `رئيسية`'s result is the exit code (the virt test device). | Tests need the exit code; the same code as hosted stops. | — |
| A64 | ~~Names of the Zicsr/privileged instructions and of the control and status registers: proposals.~~ Approved as decision 49. | — | Resolved. |
| A65 | The machine-mode layer (os/آلة.غرة): one PMP region over all memory with read/write/execute; every exception except an `ecall` from supervisor mode, and the supervisor software/timer/external interrupts, are delegated; the machine timer stays in machine mode, which reprograms it and raises a supervisor software interrupt (the tick). The M-mode trap handler runs on its own stack (in `مسودة_الآلة`). An unexpected trap in either mode prints its cause in Arabic and powers off with code 102. | The xv6 scheme: works on every RISC-V without the Sstc extension. | Sstc (`stimecmp`) once we want fewer M-mode traps. |
| A66 | In a `مترجم` build, an assembly file `X.تجميع` becomes `بناء/X.تجميع.كائن` (the hosted start file too), so it can never collide with the object of a module `X`. | Found when `معالج.تجميع` and `معالج.غرة` overwrote each other. | — |
| A67 | `رابط` defines `_نهاية` (first address after the image, end of `.bss`) and `_بداية_البيانات` (start of the writable segment, page aligned) when no object defines them. The kernel assumes QEMU's RAM: 128 MiB from `0x80000000` (`-m 128M`), without reading the device tree. | The page allocator needs the end of the kernel; the page tables need the boundary between code and data. | Read the memory size from the device tree QEMU passes in `وسيط١`. |
| A68 | Paging (os/ذاكرة/ترجمة.غرة): Sv39, the kernel mapped at its physical addresses with 4 KiB pages: code and read-only data read+execute, everything from `_بداية_البيانات` to the end of RAM read+write, the UART and the test device read+write. Accessed and dirty bits are set in every entry. The page allocator is a list of free 4 KiB pages; a page is zeroed when it is handed out. | Simple, and every later stage (user processes) builds on the same functions. | Large pages for the kernel map. |
| A69 | `make docs` (tools/docs_pdf.py): pandoc → HTML → WeasyPrint PDF. The tool lays Arabic out itself instead of relying on the renderer's bidi: letters are shaped in typing order (arabic-reshaper), the line is reversed into visual order with Latin runs kept whole, and every character is its own box, so nothing is reordered or mirrored. Headless Chrome and wkhtmltopdf were tried: Chrome does not run in the build sandbox, and wkhtmltopdf drops text under explicit bidi overrides. In the Markdown, `<samp>…</samp>` marks characters meant in storage order (shown one box each, left to right). | Works with any renderer; the result matches the editor. | — |
| A70 | `.تضمين "ملف"` (GNU `.incbin`) puts a file's bytes into the current section; the path is relative to the assembly file's directory. | The kernel image embeds the user programs (decision 46). | — |
| A71 | Stage 4 process model (docs/spec-os.md): 8 processes, per-process Sv39 tables holding the kernel (no user bit) and the process's pages (user bit) below `0x40000000`, 8 KiB kernel stacks in the kernel's `.bss`, a 272-byte trap frame (registers, `sepc`, `sstatus`), `sscratch` = kernel stack top while in user mode and ٠ in the kernel (xv6 scheme). The kernel is not preemptible: interrupts are enabled only while the scheduler idles; the supervisor may read user pages (`SUM`) after checking them in the process's table. Until stage 6 the embedded programs are ELF executables linked by `رابط` at `0x10000`, read by a minimal loader (`os/مشرف/محمل.غرة`) that maps their `PT_LOAD` segments. | Simple, testable; the ELF reading is replaced by our executable format in stage 6. | Stage 6 replaces the ELF reading. |
| A72 | File system rules (docs/spec-fs.md): a file opened for writing is always a new file at the first free block; on close it replaces any file of the same name; one writer at a time in the whole system; space of replaced files is not reused yet; no deletion or subdirectories yet. | Contiguous files stay contiguous without an allocator. | Free-space reuse and deletion when needed. |
| A73 | The virtio disk (os/جهاز/قرص.غرة): the modern MMIO interface (QEMU `-global virtio-mmio.force-legacy=false`) in the first virtio slot (`0x10001000`), one queue of 8 descriptors, one request at a time, completion by polling the used ring (no interrupt controller yet). The kernel is not preemptible, so a request is never interrupted by another. | No PLIC needed for one disk; simple and deterministic. | Interrupt-driven I/O with the PLIC once processes should run while the disk works. |
| A74 | Stage 6 loader: a program is read whole from the disk into a 64 KiB kernel buffer (larger programs are refused), checked (magic, executable flag, sizes, alignments, regions, everything below the system page), mapped with code + read-only data read/execute and data + zeroed data read/write, then its import relocations are applied in the process's pages. The system page is mapped with a software PTE bit (RSW, `ترجمة.مشتركة`) so that freeing a process's table never frees it. | Simple; programs are a few KiB. | Load page by page from the file for large programs. |
| A75 | Reading a line from the keyboard polls the UART; while nothing has arrived the process gives up the processor and tries again (no UART interrupt yet). Typed characters are echoed; backspace (127 or 8) erases a whole UTF-8 character. | No interrupt controller needed yet. | UART interrupts through the PLIC. |
