# غرة (Ghora): language specification (draft)

The language is called **غرة** (Ghora); its standard library is also called `غرة` (decision 29).

Status: **accepted** (decisions 15–32). Section headings name the decision each part follows; see [decisions.md](decisions.md).

## 0. Conventions of this document

- All code is in **file order**, the order you type it in Vim Arabic mode. In a BiDi viewer such as GitHub or a browser, numbers therefore look reversed: `{{n:255}}` is 255. The PDF made by `make docs` shows every Arabic line as the editor does (decision 48). Every number and every type name with digits in this document is generated by `tools/gen_spec.py` from the value meant, so none is reversed by hand.
- Glyphs carry their on-screen meaning (decisions 18, 21):
  - `)` `}` `]` open and `(` `{` `[` close;
  - `أ > ب` means "أ is less than ب" and `أ < ب` means "أ is greater than ب" (`>=` / `<=` likewise).
- In prose, types are named by their meaning (signed 32-bit, ...) to avoid mixing orders.

## 1. Principles (Decided 15–17)

1. Every operation has one defined meaning. Where RISC-V defines a result (overflow wraps, division by zero, shift amounts), the language uses it, at zero cost.
2. Whatever can be checked at compile time is a **compile error**. There are no warnings.
3. Safety that costs something at run time is never hidden: you ask for it by name (checked indexing `عنصر_بفحص`, checked conversions `حول_بفحص`, checked arithmetic `جمع_بفحص` …). Plain indexing is not checked at run time (decision 28).
4. Memory is managed manually. The undefined behaviour that remains is listed completely in section 10.

## 2. Lexical rules

- **Shared with the assembler:** UTF-8, the same digits and number rules, identifier characters, rejected characters, strings, escapes, `#` comments.
- **Code-point escape (Decided 25):** `\}…{`, e.g. `'\}{{h:0x200C}}{'`.
- Every statement ends with `؛` (Decided 19). Blocks are `} … {` and need no `؛` after them.
- Source files use the extension `.غرة` (Decided 29).

## 3. Types

### 3.1 Scalars (Decided 20, 24)

| Meaning | Name | `مقاس` | Values |
|---|---|---|---|
| signed 8/16/32/64 | `{{t:s8}}` `{{t:s16}}` `{{t:s32}}` `{{t:s64}}` | 1/2/4/8 | two's complement |
| unsigned 8/16/32/64 | `{{t:u8}}` `{{t:u16}}` `{{t:u32}}` `{{t:u64}}` | 1/2/4/8 | 0…2ⁿ−1 |
| size / index | `{{t:size}}` | 8 (RV64), 4 (RV32) | 0…max; the type of `.طول`, indexes, `مقاس` |
| boolean | `{{t:bool}}` | 1 | `صح` / `خطأ` only |
| character | `{{t:char}}` | 4 | one Unicode code point (not a surrogate) |

Arithmetic on integers:
- `+ - *` wrap. `/` and `باقي` follow RISC-V for division by zero and minimum ÷ −1.
- Both operands must have the same type, with no promotion. Mixing signed and unsigned is a compile error.
- Shifts: a constant shift amount out of range is a compile error; a run-time amount is masked to the width.
- Bitwise (Decided 27): `و_ب`، `أو_ب`، `أو_حصري_ب`، `نفي_ب`.
- Shift operators (Decided 31): `رفع_ب` (toward the most significant bit) and `خفض_ب` (toward the least significant). `خفض_ب` is arithmetic on signed types and logical on unsigned ones, so the type decides.
- Explicit arithmetic variants, built-in functions (Decided 31): `جمع_بفحص` / `طرح_بفحص` / `ضرب_بفحص` stop the program on overflow; `جمع_مشبع` and the others like it clamp.

Booleans: `و`، `أو` (short-circuit), `ليس`; the operands must be booleans (Decided 23). Conditions must be booleans.

### 3.2 Arrays and slices (Decided 30; indexing Decided 28)

| Type | Written | Meaning |
|---|---|---|
| array of N | `]N[نوع` e.g. `]{{n:4}}[{{t:s32}}` | N elements stored inline; a value: assignment copies; `.طول` = N at compile time |
| slice | `][نوع` | pointer + length (two words); a view, no ownership |
| read-only slice | `][ثابت نوع` | the same, but elements cannot be written through it |

- Strings are read-only slices of unsigned 8-bit: `][ثابت {{t:u8}}`. A string literal is valid UTF-8 and lives in read-only data.
- Indexing: `ش]ف[`, where the index must be of type size (Decided 28).
  - **Not checked at run time.** An index ≥ `.طول` is undefined behaviour (section 10).
  - A constant index into an array is checked at compile time, since that is free: out of range is a compile error.
  - **Checked access** is asked for by name: `عنصر_بفحص)ش، ف(` reads or writes the element and stops the program with an Arabic message if the index is out of range.
- Slicing: `ش]أ : ب[` covers elements a ≤ i < b. It is not checked at run time; a > b or b > `.طول` is undefined behaviour. The checked form is `شريحة_بفحص)ش، أ، ب(`.
- An array converts to a slice only explicitly: `م]{{n:0}} : م.طول[`. Arrays never decay to pointers.
- Array literal: `]{{n:1}}، {{n:2}}، {{n:3}}[`. The count must equal N exactly. To fill all elements with one value, write `]{{n:0}} مكرر[`.

### 3.3 Structures (Decided 30): no hidden padding

```
بنية رأس_ملف }
    سحر: ]{{n:4}}[{{t:u8}}؛
    إصدار: {{t:u16}}؛
    حشو: ]{{n:2}}[{{t:u8}}؛
    حجم_البيانات: {{t:u64}}؛
{
```

- Fields are laid out in declaration order, each at its natural alignment. The struct's alignment is the largest field alignment.
- **The compiler never inserts padding silently.** If a field would not be at its alignment, or the total size is not a multiple of the struct's alignment, it is a **compile error** saying how many bytes are missing and where. You then reorder the fields, or add explicit padding fields as in the example above. The layout in memory is exactly what you read in the source: `مقاس)رأس_ملف(` is 4 + 2 + 2 + 8 = 16.
- `بنية مضغوطة` declares a packed structure: alignment 1, no padding at all, fields may be misaligned. The compiler accesses them byte by byte, which is slower and explicit. Use it for file formats and wire protocols. You cannot take the address of a field of a packed structure, slice an array field, or loop over an array field with `لكل`: copy it into a normal variable first (the pointer could be misaligned).
- A struct value is created with every field named, in any order, and none may be missing: `رأس_ملف} سحر = …، إصدار = {{n:1}}، حشو = ]{{n:0}} مكرر[، حجم_البيانات = {{n:0}} {`.
- `==` on structures is a compile error. Compare the fields you mean, which avoids comparing padding bytes.

### 3.4 Enumerations (Decided 30)

```
تعداد لون: {{t:u8}} }
    أحمر؛
    أخضر؛
    أزرق = {{n:10}}؛
{
```

- The underlying integer type is always written. Values start at 0 and count up unless given explicitly; duplicate values are a compile error.
- Members are used qualified: `لون.أحمر`. An enumeration is not an integer; conversions are explicit (section 6).

### 3.5 Pointers and optional pointers (Decided 30)

| Written | Meaning |
|---|---|
| `^نوع` | pointer, never null |
| `^ثابت نوع` | pointer through which the value cannot be written |
| `اختياري ^نوع` | pointer that may be `لاشيء` (null) |
| `@س` | address of `س` |
| `م^` | the value `م` points to |
| `م^.حقل` | a field through a pointer (always explicit, no automatic dereference) |

- There is no pointer arithmetic: use slices.
- An optional pointer cannot be dereferenced directly. You open it with a declaration that states its type (decision 26):

```
متغير ق: اختياري ^{{t:s32}} = لاشيء؛
إذا وجد ف: ^{{t:s32}} = ق }
    ف^ = {{n:7}}؛
{ وإلا }
    # ق is لاشيء
{
```

### 3.5.1 `متطاير` (Decided 41)

`متطاير` marks memory that something other than this code also reads or writes: a device register, or a variable shared with another hart or with an interrupt handler.

```
متغير متطاير جاهز: منطقي = خطأ؛
متغير سجل: ^متطاير {{t:u8}} = اعتبر)^متطاير {{t:u8}}، {{h:0x10000005}}(؛
```

- **Where:** on a global variable (`متغير متطاير`), and on what a pointer points to (`^متطاير T`, also `^ثابت متطاير T`). Local variables, constants, parameters and slices cannot be `متطاير` (a local's address can still be passed as a `^متطاير T`).
- **What:** only scalars of 1, 2, 4 or 8 bytes: integers, `منطقي`, `حرف`, enumerations, pointers, optional pointers, functions. Not structures, arrays or slices.
- **Every access to a `متطاير` location:**
  1. happens exactly once, at exactly the type's width: never removed, repeated, merged or split;
  2. is untorn: another hart sees the whole old or the whole new value (aligned accesses; a field of a `بنية مضغوطة` can never be `متطاير`);
  3. takes part in one global order of all `متطاير` accesses of all harts, consistent with each hart's program order (sequential consistency);
  4. orders ordinary memory around it: everything written before a `متطاير` write is visible to whoever reads that value; nothing after a `متطاير` read moves before it;
  5. orders device memory (I/O) the same way, including memory a device reads by DMA.
- **Not:** a read-modify-write is two accesses (`س = س + {{n:1}}` can interleave with another hart). Atomic operations come with the A extension; `متطاير` is not a lock.
- **Types:** `^T` converts implicitly to `^متطاير T`; the other direction needs `اعتبر`. `@` of a `متطاير` global gives a `^متطاير T`.
- **Code:** every access is the load or store between two `سياج` (fence of all memory and I/O). Slower on purpose.

### 3.6 Function types (Decided 31)

`دالة)نوع، نوع(: نوع` is the type of a function value, used for callback tables. It is never null; use `اختياري` for that.

## 4. Declarations (Decided 26)

Every declaration states its type, with no exceptions:

```
متغير عدد: {{t:s32}} = {{n:0}}؛
ثابت حد: {{t:u32}} = {{n:100}}؛
ثابت تحية: ][ثابت {{t:u8}} = "مرحبا\س"؛
```

- `متغير` is a variable. It must have an initial value, or be declared with `= غير_مهيأ`. In that case the compiler proves it is assigned before every read (definite assignment); a possible read before assignment is a compile error.
- `ثابت` is a compile-time constant. Its value must be computable while compiling.
- Literals must fit their declared type exactly: `{{n:256}}` for unsigned 8-bit, or a negative value for an unsigned type, is a compile error.
- Inside a module, the order of declarations does not matter: there are no forward declarations.

## 5. Statements

### 5.1 Assignment

`س = تعبير؛`. Assignment is a statement, never an expression. There is no `++` / `--` and no `+=`.

Decided 30: `س = س + {{n:1}}؛` is the only form.

### 5.2 Conditionals (Decided 22)

```
إذا أ == ب }
    …
{ وإلا إذا أ > ب }
    …
{ وإلا }
    …
{
```

### 5.3 Selection (Decided 31): `حسب` / `حالة`

```
حسب ل }
    حالة لون.أحمر: } … {
    حالة لون.أخضر، لون.أزرق: } … {
{
```

- There is no fallthrough: each `حالة` has its own block.
- For an enumeration, every member must appear or there must be a final `وإلا: } … {`. For integers, `وإلا:` is required.

### 5.4 Loops (Decided 30)

| Form | Meaning |
|---|---|
| `طالما شرط } … {` | while: test, then body |
| `كلما } … { طالما شرط؛` | body first, then test (do-while) |
| `لكل ف: {{t:size}} من أ قبل ب } … {` | counted loop a ≤ ف < b, step 1 |
| `لكل ع: نوع في ش } … {` | over the elements of an array or slice (ع is a copy) |
| `لكل ف: {{t:size}}، ع: نوع في ش } … {` | index and element |
| `اقطع؛` / `تجاوز؛` | break / continue the innermost loop |

- Loop variables cannot be assigned inside the body.
- An infinite loop is `طالما صح } … {`.

### 5.5 Return

`ارجع تعبير؛`, or `ارجع؛` in a function without a value. A function with a result type must return on every path; the compiler checks this.

## 6. Conversions (Decided 30)

Every conversion is explicit. Its name says what happens to a value that does not fit:

| Built-in | When allowed | What it does | Cost |
|---|---|---|---|
| `حول)نوع، ق(` | only when every value of the source fits the target (widening, unsigned → wider signed, boolean → integer as 0/1, character → unsigned 32-bit, enumeration → its underlying type) | exact; checked at compile time | 0 |
| `حول_بفحص)نوع، ق(` | any integer ↔ integer, integer → character, integer → enumeration | stops the program if the value does not fit or is not a valid character / member | one comparison |
| `اقتطع)نوع، ق(` | integer → integer of any width or signedness | keeps the low bits, reinterpreted (two's complement) | 0–1 instruction |
| `اعتبر)نوع، ق(` | pointer ↔ pointer, pointer ↔ size | reinterprets the bits: **the escape hatch**, outside the language's guarantees | 0 |

- Integer → boolean has no conversion: write `ق != {{n:0}}`.
- Converting to a character can only be done with `حول_بفحص`, so an invalid character can never exist.

## 7. Functions and the ABI (Decided 30: RISC-V standard ABI)

```
عام دالة الأكبر)أ: {{t:s64}}، ب: {{t:s64}}(: {{t:s64}} }
    إذا أ < ب } ارجع أ؛ {
    ارجع ب؛
{
```

- A function without a result omits `: نوع`.
- Parameters are passed by value and cannot be assigned. To pass something by reference, pass a pointer.
- There are no variadic functions, which removes the `printf` class of bugs. No overloading, no default arguments.
- **Calling convention: RISC-V LP64 integer ABI, exactly**, so the language, our assembly and C compiled by GCC can call each other:
  - arguments in `وسيط٠`…`وسيط٧`, the rest on the stack; results in `وسيط٠` (and `وسيط١` for two-word results);
  - `محفوظ٠`…`محفوظ١١` are preserved by the callee; `مؤشر_المكدس` is 16-byte aligned;
  - 8/16/32-bit arguments are extended to 64 bits as the ABI says (signed: sign-extended; unsigned 8/16: zero-extended; unsigned 32: sign-extended, as RV64's ABI requires);
  - a slice is a two-word structure (pointer, length): two registers;
  - structures of up to two words travel in registers, larger ones by reference, as the ABI specifies.
- **Program entry:** the root module exports `رئيسية`. A small start file provides `_بداية`, which calls it with the command-line arguments and exits with its result:

```
عام دالة رئيسية)وسائط: ][][ثابت {{t:u8}}(: {{t:u8}} }
    ارجع {{n:0}}؛
{
```

The result type is unsigned 8-bit because that is exactly what a Linux exit code can hold.

## 8. Modules (Decided 30)

### 8.1 Within a project

- **One file is one module.** The directory tree is the namespace: `رياضيات/مصفوفات.غرة` is the module `رياضيات.مصفوفات`.
- `استورد رياضيات.مصفوفات؛` makes the module available. Its members are used qualified by the last part of the name, `مصفوفات.ضرب)…(`. With a local name: `استورد نصوص باسم ن؛`, then `ن.اطبع)…(`. Unqualified imports do not exist, so a name can never silently come from two places.
- Everything is private by default; `عام` exports it.
- Imports must not form a cycle (compile error naming the cycle). The build order is therefore always defined.
- No preprocessor and no textual inclusion. Constants are `ثابت`.

### 8.2 Third-party code and pre-compiled modules

- A module can be imported from its **source** or from its **compiled object**. The compiler searches:
  1. the project root;
  2. the directories given with an option, conventionally `مكتبات/<اسم>/`;
  3. the standard library `غرة` (its modules are imported as `غرة.…`, e.g. `استورد غرة.نصوص؛`).
- **Every object file of ours carries the module's interface:** exported names, their full types, structure layouts, enumeration members and constant values. Importing a compiled module therefore needs only its object. There are no header files that can drift out of sync, and the interface can be read with the text form of the object format (decision 12).
- **Consistency check.**
  - Each object stores a hash of its own interface and the hashes of the interfaces it was compiled against.
  - The linker refuses to combine objects built against a different version of an interface, and says which module is stale.
  - That catches C's classic "header changed, object not rebuilt" bug at link time.
- **Libraries:** several compiled modules can be bundled into one library file (our archive format, designed with the object format). The linker takes from it only the modules that are imported.
- **Foreign code** (our assembly, or C compiled to ELF):

```
خارجي دالة اكتب)ملف: {{t:s32}}، بيانات: ][ثابت {{t:u8}}(: {{t:s64}}؛
```

  `خارجي` declares a function implemented elsewhere, with its full signature, under its raw symbol name. `عام خارجي دالة …` does the opposite: it exports a function under its raw name so assembly or C can call it.

### 8.3 Symbol names in objects

- Exported names are qualified with the module path (`رياضيات.مصفوفات.ضرب`), so two modules may both have a `ضرب`.
- `خارجي` names are used exactly as written, for interop.
- The three linkage kinds — private, exported, imported — are the object format's only symbol kinds (decision 11).

## 10. Undefined behaviour: the complete list

1. Use of memory after it has been freed, or of a pointer to a local variable after its function has returned.
2. Plain indexing or slicing out of range (`ش]ف[`, `ش]أ : ب[`) at run time. Use `عنصر_بفحص` / `شريحة_بفحص` where you want the check (decision 28).
3. Anything done through `اعتبر` that produces a pointer to memory that is not a valid object of that type.
4. Hand-written assembly or foreign code that breaks the ABI.

Nothing else is undefined.
